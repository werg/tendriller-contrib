# Historical private-response and approval evidence

The [recorded evidence](evidence.json) preserves the exact public artifacts,
reference digests and three actual Worker scenarios from the former hosted
workflow executor. The [last source snapshot](https://github.com/werg/tendriller-contrib/tree/646ceca52c1cd4c164ef3af7c9bddeba3e3df90f/cookbooks/collect-private-responses)
retains its private-response reference, browser adaptations and host runner. The
[proposal reference](https://github.com/werg/tendriller-contrib/blob/646ceca52c1cd4c164ef3af7c9bddeba3e3df90f/cookbooks/review-exact-proposal/snippets/approval.mjs)
was exercised by that same historical runner.

Those application executors and their fixtures are retired. The current host is
a selective Chronolog participant for control, discovery and signed code
publication. Application commands, queries, content and operation journals use
one owned session. See the [current public-artifact gates](../../run-a-peer-application/checks/README.md).

A new private-response application must qualify actual reader membership and
key access, guarded submission, exact retry, removal of access, and deliberate
publication of an aggregate. Filtering a query or hiding a private UI does not
limit what an authorized history reader can decrypt. Text-only historical
records do not establish private-media access, retention, current membership
behavior or an external effect guarantee.
